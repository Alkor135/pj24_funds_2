# pj24_funds_2

## Структура проекта

В корне находятся семь запускаемых Python-скриптов:

- `forecast_mix.py` — создание дневных вероятностей MIX.
- `forecast_rts.py` — создание дневных вероятностей RTS.
- `research_real.py` — исследование результатов Real по двум готовым книгам.
- `research_real_groups.py` — два DataFrame с количествами и суммами Real по
  фиксированным интервалам Рост/Падение, выводимые в консоль.
- `research_real_regime_groups.py` — такие же DataFrame по колонкам
  Бычий/Медвежий, выводимые в консоль.
- `research_real_regime_trades.py` — количество сделок и доход по порогам
  Бычий/Медвежий, отдельно и суммарно, до и после комиссии в б.п.
- `research_real_regime_ranges.py` — подбор отдельных диапазонов покупки/продажи
  для MIX и RTS с шагом 5%, непрерывная симуляция и автономный HTML.

`source/` содержит девять вспомогательных модулей и объявление пакета Python;
описания модулей и примеры находятся в `source/README.md`. `tests/` содержит
тесты и проверочные скрипты, `outputs/` — результаты, `research_sources/` —
сохранённые материалы исследования. Команды и параметры запуска сохранены.
При запуске по абсолютному пути из другой папки пакет `source` находится
автоматически. Стандартные результаты сохраняются в `outputs` корня проекта;
явно заданные относительные пути отсчитываются от рабочей папки запуска.

## Диапазоны вероятностей и автономная симуляция за всю историю

`research_real_regime_ranges.py` подбирает четыре отдельных диапазона:
покупки/продажи MIX и покупки/продажи RTS. Для каждого инструмента совместно
выбирает пару с максимальным совокупным P&L после комиссии **на всей истории**.
Границы: 0%, 5%, …, 100%. Для направления проверяются все 210 непрерывных
диапазонов и отключение торговли; всего 211 × 211 = 44 521 пара на инструмент.
Нижняя граница включена, верхняя исключена, кроме включённых 100%.
При равном доходе с точностью 1e-8 пункта выбирается меньше сделок, меньшая
суммарная ширина, затем меньшие границы покупки и продажи.

Покупка проверяет колонку «Бычий», продажа — «Медвежий» выбранного листа,
включая сохранённое округление. Дополнительные фильтры по наблюдаемому режиму
и числу обучающих примеров не применяются. При двух сигналах сделка пропускается.
Один контракт: вход OPEN → выход CLOSE того же дня; покупка даёт Real,
продажа — −Real. Комиссия по умолчанию 3 б.п. на полный круг от OPEN:
`OPEN × 3 / 10000` пунктов, без повторного списания на выходе.
Прочие расходы и проскальзывание не моделируются. Real=0 — сделка с комиссией;
пустой Real — неисполненный сигнал, учитываемый отдельно.
Цены читаются из SQLite по Дата/SECID/LSTTRADE; проверяется `Real=CLOSE−OPEN`.
Серия XLSX должна соответствовать выбранному инструменту; входы не изменяются.
Запрещена перезапись фактической SQLite из аргументов или метаданных книги
путём сохранения отчёта в тот же файл, включая БД с нестандартным расширением.

Результат по умолчанию: `outputs/regime_ranges/report.html`, один автономный
HTML, который перезаписывается при повторном запуске. Внутри отдельные разделы
MIX/RTS, выбранные диапазоны, три непрерывных SVG-графика на инструмент: совокупный P&L
с обеими сторонами, отдельно покупки, отдельно продажи. **Кривые идут по всей
истории, сохраняют дни без исполнения и не обнуляются между годами.**
Для каждого инструмента добавлен четвёртый SVG-график: годовой столбчатый PnL.
Для каждого года рядом показаны три столбца — всего, покупки, продажи после
комиссии в пунктах. Это результат отдельного года без накопления между годами;
убытки отображаются ниже нуля, годы без сделок сохраняются. Наведение курсора
на столбец показывает год, направление и точное значение.
График можно развернуть кнопкой; Escape сворачивает. Файл открывается локально
без интернета и соседних ресурсов. Подбор и симуляция выполнены на одних данных:
это исторический максимум, без отдельной проверки на последующем периоде.

Отчёт содержит показатели за всю историю и по каждому году для совокупности
и каждой стороны: число сделок, P&L до/после комиссии, комиссия, доля побед,
profit factor, максимальная просадка, фактор восстановления, средняя/медианная,
лучшая/худшая сделки, средние выигрыши/убытки и сигналы без Real.
Win rate и profit factor считаются **после комиссии**; просадка учитывает
начальный ноль. Основная годовая таблица показывает восемь основных метрик;
блок «Все показатели по отдельным годам» раскрывает полный набор для каждого года.
Годовая просадка считается внутри года, полная — с переходами
между годами. P&L и количество сделок по годам складываются в полные показатели.
Без модели капитала доход и просадка выражены в пунктах, без реинвестирования;
пункты MIX и RTS не складываются. Если убыточных сделок нет при наличии прибыли,
profit factor отображается как ∞; неопределённые показатели — как прочерк.

Дополнительно внутри HTML: 12 лучших пар, полный журнал сделок/пропусков,
SHA-256 входной книги и встроенный JSON с каждой датой симуляции.
Кнопка «Скачать сделки CSV» выгружает исполненные сделки инструмента из
встроенных данных: UTF-8 с BOM, разделитель `;`, вероятности в долях 0–1.
Логи не создаются. Используются существующие зависимости `requirements.txt`.

```powershell
.\.venv\Scripts\python.exe research_real_regime_ranges.py
.\.venv\Scripts\python.exe research_real_regime_ranges.py --only RTS --commission-bps 3
.\.venv\Scripts\python.exe research_real_regime_ranges.py --mix outputs/MIX_probabilities.xlsx --rts outputs/RTS_probabilities.xlsx
.\.venv\Scripts\python.exe research_real_regime_ranges.py --only MIX --mix-db C:/data_quote/day2/MIX_day2.db
.\.venv\Scripts\python.exe research_real_regime_ranges.py --output outputs/regime_ranges/report.html
.\.venv\Scripts\python.exe research_real_regime_ranges.py --help
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_regime_ranges.py -v
```

Параметры: `--mix`/`--rts` — книги (по умолчанию соответствующие XLSX в `outputs`
рядом со скриптом); `--mix-db`/`--rts-db` — копии SQLite (по умолчанию Источник
из листа «Параметры»); `--only MIX|RTS` — один инструмент вместо обоих;
`--sheet` — лист вероятностей (по умолчанию «Прогноз»); `--commission-bps` —
конечная неотрицательная комиссия на круг (по умолчанию 3); `--output` —
путь HTML (по умолчанию `outputs/regime_ranges/report.html` рядом со скриптом).
Явные относительные пути отсчитываются от текущей рабочей папки.
Код завершения: 0 при успехе, 2 при ошибке.

`source/regime_ranges.py` выполняет подбор и симуляцию;
`source/regime_ranges_report.py` создаёт HTML. Проверки — в `tests/test_regime_ranges.py`.

## Real по десяти интервалам Рост и Падение

`research_real_groups.py` читает выбранный XLSX и создаёт два pandas DataFrame:
`df_growth` для колонки «Рост» и `df_decline` для «Падение». Каждый содержит
10 строк. Порядок колонок:

- `df_growth`: «Группа», «Количество Real > 0», «Количество Real < 0»,
  «Сумма Real > 0», «Сумма Real < 0», «разница».
- `df_decline`: «Группа», «Количество Real < 0», «Количество Real > 0»,
  «Сумма Real < 0», «Сумма Real > 0», «разница».

«разница» в обоих DF равна сумме двух колонок сумм с сохранением знаков:
`Сумма Real > 0 + Сумма Real < 0`. Например, 100 + (−40) = 60.

Интервалы фиксированы: `[0%; 10%)`, `[10%; 20%)`, …, `[90%; 100%]`.
Граничные 10%, …, 90% входят в следующую группу; 100% входят в последнюю.
В исходных книгах проценты хранятся как доли: 0.1 соответствует 10%.
Используются значения Рост/Падение именно выбранного листа, а не исходные
вероятности листа «Диагностика». Пропуски вероятности исключают строку только
из соответствующего DF. Real=0 и пустые Real не учитываются; отрицательные
суммы сохраняют знак минус. Пустые группы выводятся с нулями.

Исследуется вся таблица без фильтра по размеру истории, разделения периодов
и списания расходов. Суммы и разница относятся к исходному Real в пунктах;
в консоли они показаны с двумя знаками после точки. Скрипт печатает оба DF, не создаёт
файлов результатов и не изменяет исходную книгу. Требуется pandas вместе
с numpy/openpyxl из `requirements.txt`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe research_real_groups.py
.\.venv\Scripts\python.exe research_real_groups.py --input outputs/RTS_probabilities.xlsx
.\.venv\Scripts\python.exe research_real_groups.py --input C:/data/table.xlsx --sheet Прогноз
.\.venv\Scripts\python.exe research_real_groups.py --help
```

Параметры: `--input` — путь XLSX (по умолчанию `outputs/MIX_probabilities.xlsx`
рядом со скриптом); `--sheet` — лист (по умолчанию «Прогноз»). Обязательные
колонки: Рост, Падение, Real. Нечисловые/бесконечные значения и вероятности
вне диапазона 0–1 вызывают ошибку. Успешный запуск возвращает код 0,
ошибка чтения/анализа — 2. Проверки:
`python -m unittest discover -s tests -p test_real_groups.py -v`.

Для использования DF из другого Python-кода:

```python
from pathlib import Path
from research_real_groups import load_real_groups

df_growth, df_decline = load_real_groups(Path("outputs/MIX_probabilities.xlsx"))
```

Общие функции `analyze_real_groups(data, probability_columns=("Рост", "Падение"))`
и `load_real_groups(path, sheet="Прогноз", probability_columns=("Рост", "Падение"))`
также поддерживают другую пару колонок вероятностей. Параметр
`probability_columns` передаётся по имени. Первый DF содержит положительные
показатели перед отрицательными; второй — отрицательные перед положительными.

## Real по десяти интервалам Бычий и Медвежий

`research_real_regime_groups.py` читает колонки «Бычий», «Медвежий» и Real
из выбранного XLSX и создаёт два pandas DataFrame по 10 строк. Порядок колонок:

- `df_bull`: «Группа», «Количество Real > 0», «Количество Real < 0»,
  «Сумма Real > 0», «Сумма Real < 0», «разница».
- `df_bear`: «Группа», «Количество Real < 0», «Количество Real > 0»,
  «Сумма Real < 0», «Сумма Real > 0», «разница».

Правила те же, что для Рост/Падение: фиксированные интервалы `[0%; 10%)`,
`[10%; 20%)`, …, `[90%; 100%]`; 100% входят в последнюю группу. Вероятности
хранятся как доли 0–1 и берутся именно из выбранного листа. Real=0 и пустые
Real не учитываются; пропуск вероятности исключает строку только из её DF.
Пустые группы выводятся с нулями. «разница» в обоих DF равна
`Сумма Real > 0 + Сумма Real < 0` с сохранением знаков.

Скрипт исследует всю таблицу без дополнительных фильтров и расходов,
используя общие функции из `research_real_groups.py`. Печатает результаты
в пунктах с двумя знаками после точки, исходную книгу не меняет. Зависимости
уже перечислены в `requirements.txt`; дополнительных библиотек не требуется.

Параметры: `--input` — путь XLSX (по умолчанию `outputs/MIX_probabilities.xlsx`
рядом со скриптом); `--sheet` — лист (по умолчанию «Прогноз»). Ошибки чтения

## Доход сделок по порогам Бычий и Медвежий

`research_real_regime_trades.py` моделирует покупку при вероятности Бычий
не ниже 60% и продажу при вероятности Медвежий не ниже 70%. Целые и дробные пороги включаются
и настраиваются через `--bull-threshold` и `--bear-threshold` (проценты 0–100).
Значения по умолчанию также заданы константами в начале кода.

Модель: один контракт на сделку, вход по OPEN и выход по CLOSE того же
дневного бара. Доход покупки равен Real, продажи — −Real. Доходы суммируются
в пунктах без реинвестирования. Комиссия на полный круг по умолчанию 3 б.п.
(0.03%) от цены входа: `OPEN × 3 / 10000` пунктов на сделку. Параметр
`--commission-bps` позволяет изменить её; повторно за выход комиссия не
списывается. Отдельно выводятся доход без комиссии, сумма комиссий и доход
с комиссией.

Сводный DF содержит строки «Бычий: покупка», «Медвежий: продажа», «Всего»
и колонки «Режим», «Количество сделок», «Доход без комиссии», «Комиссия»,
«Доход с комиссией», «Сигналы без Real». Real=0 учитывается как сделка
с комиссией. Пустой Real исключается из числа сделок и дохода, но считается
в «Сигналы без Real». Пустая вероятность не даёт сигнал. При выполнении
обоих условий в один день этот день пропускается; число конфликтов печатается
перед таблицей. Анализируется вся таблица без дополнительных фильтров истории.

Вероятности и Real читаются из выбранного листа XLSX. Для комиссии в пунктах
OPEN берётся из исходной SQLite по точному ключу Дата/SECID/LSTTRADE.
Путь БД и серия берутся из листа «Параметры»; `--db` позволяет указать другую
копию БД. Проверяются цены и равенство Real=CLOSE−OPEN; несоответствие вызывает
ошибку. XLSX и SQLite не изменяются, файлы результатов не создаются.

```powershell
.\.venv\Scripts\python.exe research_real_regime_trades.py
.\.venv\Scripts\python.exe research_real_regime_trades.py --input outputs/RTS_probabilities.xlsx
.\.venv\Scripts\python.exe research_real_regime_trades.py --input outputs/RTS_probabilities.xlsx --bull-threshold 65 --bear-threshold 75 --commission-bps 3
.\.venv\Scripts\python.exe research_real_regime_trades.py --db C:/data_quote/day2/MIX_day2.db --sheet Прогноз
.\.venv\Scripts\python.exe research_real_regime_trades.py --help
```

По умолчанию `--input` — `outputs/MIX_probabilities.xlsx` рядом со скриптом,
`--sheet` — «Прогноз». Явно заданные относительные пути отсчитываются от
рабочей папки запуска. Требуются pandas, numpy и openpyxl из `requirements.txt`.
Успех возвращает код 0, ошибка — 2. Проверки:
`python -m unittest discover -s tests -p test_real_regime_trades.py -v`.

Функция `analyze_regime_trades(data, bull_threshold=60, bear_threshold=70,
commission_bps=3)` возвращает сводный DF по колонкам Бычий, Медвежий, Real,
OPEN; `load_regime_trade_data(path, sheet="Прогноз", db=None)` возвращает
подготовленный DF и путь использованной БД.

## Исследование Real

`research_real.py` — основной запуск исследования двух готовых XLSX.
`source/real_reports.py` сохраняет CSV с BOM для Excel, JSON параметров и результатов,
PNG-графики и русский документ. Выходы имеют постоянные имена и перезаписываются.
На графиках условных результатов и калибровки указаны размеры групп;
подписи разнесены, чтобы соседние значения оставались читаемыми.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe research_real.py
.\.venv\Scripts\python.exe research_real.py --cost-bps 3 --bootstrap-repeats 2000 --seed 42
.\.venv\Scripts\python.exe research_real.py --cost-scenarios-bps 0 2 3 5 10
.\.venv\Scripts\python.exe research_real.py --help
```

Входы по умолчанию: `outputs/MIX_probabilities.xlsx` и `outputs/RTS_probabilities.xlsx`.
Артефакты: `outputs/real_research/MIX` и `outputs/real_research/RTS`; общие данные —
`outputs/real_research/summary.json`. Документ `Исследование_Real_результаты.md`
сохраняется в папку Obsidian проекта. Пути можно изменить через `--mix`, `--rts`,
`--output-dir` и `--report`; документ должен иметь расширение `.md`.

`--cost-bps` по умолчанию 3 означает расходы на полный круг, включая исполнение.
`--cost-scenarios-bps` задаёт список расходов; основные и стрессовые расходы
добавляются автоматически. Остальные параметры: `--min-history` (200),
`--min-train-trades` (60), `--min-validation-trades` (30), `--min-test-trades` (30),
`--bootstrap-repeats` (2000), `--seed` (42).

Календарь делится 60/20/20 до исключения пропусков. Границы групп фиксируются
по обучению; покупка и продажа выбираются отдельно на следующем участке.
Изменение фактов теста не меняет выбор и сигналы. При конфликте день пропускается.
Отсутствие подходящего правила — допустимый результат. Кривая представляет
сумму результатов изменения цены при единичной экспозиции, без модели капитала.
Отчёт не является прогнозом текущего дня и не проверяет внутридневные стопы.
Полные окна определяются по W_max/V_max исходных книг. Матрицы, размеры истории
и прогнозы проверяются на согласованность. Для статистического заключения нужно
не менее 1000 блочных повторов с пригодными оценками; меньшее число разрешено
только как диагностический запуск. Низкая история режима влияет на конкретное
режимное правило и не запрещает независимый сигнал другого направления.

`source/real_validation.py` выполняет четыре проверки на следующих участках истории,

### Методика и контракты

Профиль, подтверждённый пользователем: **полный дневной бар Day**. Колонка
«Дата» означает TRADEDATE целевого бара, движение — его OPEN → CLOSE, режим —
состояние на его закрытии. Это не отдельная основная сессия внутри дня.
Источник правил: `Стратегия_фондов_методика_таблицы.md` в папке документов проекта.

История контракта объединяется по **LSTTRADE**. Изменение SECID при сохранении
экспирации не запускает прогрев заново. Цены разных экспираций не соединяются.
Для каждой целевой даты выбирается минимальная ранее наблюдавшаяся экспирация
строго позже этой даты. На самой дате экспирации выбирается следующий контракт.
В истории за дату обучается **один основной контракт**, а не оба доступных.
Его предыдущий режим берётся из его собственной истории, включая период до
выбора основным. SECID в XLSX — алиас выбранной экспирации из целевого бара;
он используется только для отображения. Для будущей цели берётся последний
известный SECID. Первая дата БД содержит идентификаторы из её строки только
для отображения и не имеет прогнозных процентов.

При нескольких алиасах на одной дате и экспирации одинаковые OPEN/CLOSE/VOLUME
не удваивают наблюдение; выбирается SECID по возрастанию. Конфликт цен или
объёма вызывает ошибку, чтобы не смешать разные бары молча.

Режим: `g=ln(C_t/C_(t-L))`, граница `k × sigma_CC × sqrt(L)`. sigma_CC
оценивается с ddof=1 по прошлым доходностям, исключая классифицируемую текущую.
Первые 21 последовательное закрытие дают режим при 19 предыдущих доходностях.
Полное окно 60 со сдвигом требует 62 закрытия. Для цели следующего бара
граница режима включает последнюю уже завершённую доходность.

Движение: `y=ln(CLOSE/OPEN)`, граница `epsilon=q × sigma_OC` из максимум 60
**предыдущих** последовательных пригодных результатов. Равенство границе
относится к Flat/Боковому. Недостаточная или нулевая волатильность даёт NA.
Положительные перенесённые CLOSE используются в режиме; `FilledQuotes` и
`VOLUME=0` исключаются из движения и обрывают его последовательное окно.
Отсутствующая строка контракта обрывает историю, календарь не сжимается.

Две модели считают `S_(i-1) → Y_i` и `S_(i-1) → S_i` отдельно. Вероятность
исхода: `(счётчик + alpha)/(n + 3 × alpha)`. Если условная строка пуста,
используется общая история этой модели с явным `FALLBACK_UNCONDITIONAL`.
Если истории нет или границы целевого класса не определены, ячейки пусты.
Наблюдаемый режим NA не подменяется Боковым.

### Содержание XLSX

- **Прогноз:** десять колонок: Дата, SECID, LSTTRADE, Рост, Падение,
  Флэт, Бычий, Медвежий, Боковой, Real. Даты и вероятности
  записаны как значения соответствующих типов; даты показаны как `ГГГГ-ММ-ДД`,
  включены фильтр и закрепление.
  Тройки показаны с одним десятичным знаком и суммой 100.0% после распределения
  остатков. Пустое значение означает NA, а не вероятность 0%.
  «Флэт» — прежнее «Незначительное изменение» с тем же классификационным порогом.
  `Real` — фактическое изменение `CLOSE − OPEN` выбранного контракта в пунктах:
  рост положителен, падение отрицательно, отсутствие изменения равно нулю.
  Оно выводится и до прогрева вероятностной модели, если есть реальные цены.
  Для будущей даты, отсутствующего бара, `FilledQuotes` или `VOLUME=0` поле пустое.
  Формат Real — число с двумя десятичными знаками; в XLSX хранится исходная
  разность без округления. Real не является доходностью, числом шагов цены
  или денежной прибылью и не участвует в прогнозе своей даты.
- **Диагностика:** исходные доли полной точности, наблюдаемый режим, источники
  оценок, реальные размеры строк, размеры окон, пороги и границы, снимки
  обеих матриц счётчиков, статусы и отдельно факты завершившихся баров.
  Факты не участвуют в прогнозе своей даты.
- **Параметры:** источник и SHA-256 БД, версия модели, время создания XLSX
  со смещением +03:00, параметры, правила и ограничения.

### Ограничения воспроизводимости

В дневных БД нет времени первоначальной доступности цен, паспортов границ
агрегации и истории доступности метаданных. XLSX — **причинная реконструкция
по текущему снимку**, которая не доказывает фактическую публикацию прогнозов
до исторических открытий. Время создания XLSX не выдается за время выпуска
исторического прогноза. Поздние исправления БД и FilledQuotes могут влиять
на реконструкцию. SHA-256 фиксирует использованный файл; при изменении БД
во время расчёта скрипт прекращает работу.

Календарь строится из уникальных TRADEDATE каждой БД. Пропуск всех контрактов
сразу не обнаруживается без внешнего торгового календаря. Бары одной серии
не дополняются датами другой серии. Никакие отсутствующие строки не создаются.

Статус моделей **UNVALIDATED**. Проценты — оценки частот модели, их калибровка,
качество на независимом периоде и торговое преимущество здесь не проверяются.
Повторный расчёт по изменённой БД создаёт новую реконструкцию; исходный XLSX
не заменяется без `--overwrite`.
